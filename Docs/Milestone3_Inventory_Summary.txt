MILESTONE 3 - INVENTORY BASICS: WORK SUMMARY
Project: Module10_TNI (Unity 6.3 LTS, URP, Input System)
Scene: ThirdPerson
Date: 31 Oct 2026

==================================================================
OVERVIEW
==================================================================
The ThirdPerson scene now has a small inventory:
- Coins, health potions and a gem lie near the player start.
- Look at one and press E to pick it up (uses the existing interaction system).
- A hotbar of 6 slots at the bottom-centre shows icons and stack counts.
- Keys 1-6 select a slot, Q uses the selected item.
- A Health Potion heals 25 and the green health bar goes up.

All new student scripts are written in Unity tutorial style with explanatory
comments: plain methods, simple ifs, string names for input actions,
no lambdas / LINQ / => members / singletons.

==================================================================
SPRINT 6 - ITEM DATA AND INVENTORY CORE
==================================================================
- ItemData (ScriptableObject): name, icon, max stack size, heal amount.
- Assets: Coin (stack 99), HealthPotion (stack 5, heals 25), Gem (stack 1).
- Generated 64x64 icons in Assets/Items/Icons, imported as Sprite (2D and UI).
- InventorySlot (item + count) and Inventory (6 slots, AddItem stacks first then
  uses empty slots and returns false when full, RemoveItem, selected slot).
- Teacher tools: Tools > Setup Inventory Scene, Tools > Validate Inventory.

Problem found and fixed:
- Opening a scene from the setup script unloaded the ItemData objects it had just
  made. The script now opens the scene first and creates assets after.

==================================================================
SPRINT 7 - WORLD PICKUPS
==================================================================
- ItemPickup (IInteractable): "Press E to pick up <name>", adds to the Inventory
  and destroys itself; stays and logs "Inventory full" when there is no room.
- URP Lit materials in Assets/Items/Materials.
- ItemPickups group in ThirdPerson: Coin_1..5 (left), HealthPotion_1..2 (right), Gem_1.

==================================================================
SPRINT 8 - HOTBAR UI
==================================================================
- HotbarSlotUI: one box (background, icon, count, highlight).
- HotbarUI: copies every inventory slot into its box every frame (same idea as
  HealthBar: always correct, very cheap for 6 slots).
- HUDCanvas/Hotbar with Horizontal Layout Group, anchored bottom-centre.

==================================================================
SPRINT 9 - SELECTING AND USING ITEMS
==================================================================
- Input actions Slot1..Slot6 (keys 1-6) and UseItem (Q) added to the Player map.
- PlayerItemUser: selects slots, uses the selected item. Not usable -> "Can't use <name>".
  Full health -> potion is kept. Dead -> nothing happens.
- Health.Heal(amount): clamped at MaxHealth, does nothing when dead.
  (No other change to Health or any combat script.)

KNOWN DEBT (carried forward)
==================================================================
Inventory:
- Not confirmed in Play mode yet.
- Template actions Previous / Next are also bound to keys 1 and 2. No script uses
  them today, but a future script that does would fire together with Slot1 / Slot2.
- Pickups add one item each; there is no "amount" per pickup.
- Pickups are plain scene objects, not prefabs. No drop / throw yet.
- "Inventory full" is only shown in the Console, not on screen.
- HotbarUI refreshes every frame. Fine for 6 slots; events would scale better.
- The inventory is not saved between scenes or sessions.
- Selecting slots still works after death (using does not). PlayerDeath was not
  changed, by request.
- FirstPerson scene has no inventory.
- Small coins need careful aiming with the crosshair from the third-person camera.
- InventoryValidation calls Awake through SendMessage to simulate starting the game.
From Milestone 2 (unchanged):
- Raycast damage lands on the click, before the hit visibly connects.
- Jump is not blocked while kicking. A trigger set in the air can fire on landing.
- Dying in the air freezes the player in the air. No restart or "You Died" screen.
- Enemy damage uses a fixed 0.5 s delay. AttackEventRelay.cs is unused.
