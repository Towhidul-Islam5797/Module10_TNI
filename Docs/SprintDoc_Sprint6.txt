SPRINT 6 - ITEM DATA AND INVENTORY CORE (ThirdPerson scene)
Milestone 3: Inventory Basics

GOAL
Items exist as assets, and the player has an Inventory of 6 slots that can
add and remove items, with stacking.

HOW IT WORKS (in plain words)
- ItemData is a ScriptableObject. It is not on a GameObject; it is an asset file
  in the Project window, like a recipe card. It stores the item's name, icon,
  how many fit in one slot (max stack size) and how much it heals (0 = not usable).
  Every coin in the world points to the same Coin asset.
- InventorySlot is a tiny class with two fields: which item, and how many.
  It is marked [System.Serializable] so you can watch it in the Inspector.
- Inventory is a component on the Player. In Awake it makes a List of 6 empty slots.
  AddItem(item) looks in two steps:
    1. Is there a slot with the same item that still has room? Add 1 there.
    2. Otherwise, is there an empty slot? Put the item there with count 1.
    If neither works, the inventory is full: it logs that and returns false.
  RemoveItem(slotIndex) takes one away. At 0 the slot is cleared (item = null).
  The Inventory also remembers which slot is selected (used by the hotbar later).
- Every add and remove is written to the Console, so you can follow along.
