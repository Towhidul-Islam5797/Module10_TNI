SPRINT 12 - DRAG AND DROP, CRAFTING THROUGH THE UI (ThirdPerson scene)
Milestone 4: Crafting System

GOAL
With the panel open, drag items from the hotbar into the 3x3 grid. When the grid matches a
recipe, a half-transparent preview appears on the result slot. Drag the preview to the
hotbar to really craft it. Items in the grid can be dragged back to the hotbar.

HOW IT WORKS (in plain words)
- Unity's drag-and-drop interfaces (UnityEngine.EventSystems). A script that "implements"
  them gets these calls from the EventSystem:
    IBeginDragHandler.OnBeginDrag   a drag starts on this box
    IDragHandler.OnDrag             every frame of the drag
    IEndDragHandler.OnEndDrag       the mouse button was let go (on the box the drag STARTED on)
    IDropHandler.OnDrop             the mouse button was let go ON this box
  Order when letting go: OnDrop on the target first, then OnEndDrag on the source.
  They need: an EventSystem, a GraphicRaycaster, and Raycast Target on the box image.
- Which box did the drag come from? eventData.pointerDrag is the GameObject the drag
  started on. The target uses GetComponent to see if it is a HotbarSlotUI or a CraftingSlotUI.
- ItemDragUI (HUDCanvas/DragIcon, the last child so it draws on top) is only a picture:
  BeginDrag shows it, Follow moves it to the mouse, EndDrag hides it and logs
  "Drag cancelled" if the mouse was not over any box. Its Raycast Target is off,
  otherwise it would sit under the mouse and block the drop.
- Nothing changes while dragging. Data only changes in OnDrop, through CraftingGrid:
    hotbar box -> grid box     CraftingGrid.MoveToGrid(hotbar index, grid index)
                               one item moves; an occupied box says no
    grid box   -> hotbar       CraftingGrid.MoveGridToInventory(grid index)
    result     -> hotbar       CraftingGrid.MoveResultToInventory()  (crafts the preview)
  Because a failed or cancelled drop changes nothing, there is nothing to undo.
- While a box is the source of a drag, its icon is drawn half transparent (isBeingDragged).
  The every-frame refresh puts it back to normal as soon as the drag ends.
- Dropping onto the hotbar always uses Inventory.AddItem, so the normal stacking rules decide
  the slot, whichever hotbar box you drop on.
- HotbarSlotUI only allows dragging while CraftingPanelUI.IsOpen. It remembers the slot it drew
  last (shownSlot), so it still does not need a reference to the Inventory.
- If the panel closes in the middle of a drag, CraftingSlotUI.OnDisable hides the drag icon
  (a hidden object gets no more drag events).

MANUAL PLAY-MODE TEST (teacher)
1. Press Play. Pick up 5 coins. Press C.
2. Drag the coin box onto a grid box: the hotbar count drops by 1, the coin appears in the
   grid. While dragging, the icon follows the mouse and the hotbar icon is half transparent.
3. Drag coins into 3 more grid boxes (any boxes). After the 4th: a half-transparent Gold Bar
   appears on the result slot. Console: "Recipe found: Gold Bar...". The hotbar has 1 coin.
4. Drag one coin from the grid back to the hotbar: the preview disappears. Put it back.
5. Drag a coin onto a grid box that already holds a coin: "...already holds Coin. Drop rejected."
6. Drag the coin box and let go over empty screen: "Drag cancelled...". Nothing changed.
7. Drag the Gold Bar preview onto any hotbar box: Console "Crafted Gold Bar from 4 Coin",
   the Gold Bar is in the hotbar, the grid and result slot are empty.
8. Put 2 coins in the grid and press C: they go back to the hotbar.
9. Close the panel: dragging the hotbar does nothing; play works as before.
