SPRINT 10 - RECIPES, NEW ITEMS AND THE CRAFTINGGRID LOGIC (ThirdPerson scene)
Milestone 4: Crafting System

GOAL
Recipes exist as assets. The Player has a CraftingGrid that can craft and uncraft.
There is no crafting UI yet: everything is tested by the validation tool, without Play mode.

HOW IT WORKS (in plain words)
- CraftingIngredient is one line of a recipe: an item and a count ("4 Coin").
- CraftingRecipe is a ScriptableObject (like ItemData): a list of ingredients, a
  result item and a result count. Three recipe assets live in Assets/Crafting/Recipes:
    GoldBar          4 Coin                   -> 1 Gold Bar
    BigHealthPotion  2 Health Potion + 1 Gem  -> 1 Big Health Potion (heals 60)
    GemRing          1 Gold Bar + 1 Gem       -> 1 Gem Ring
  GemRing needs a Gold Bar, so it is a two-step recipe: Coins -> Gold Bar -> Gem Ring.
- CraftingGrid (on the Player) holds 9 grid slots and 1 result slot. It reuses
  InventorySlot, so a grid slot is the same idea as an inventory slot. Each grid slot
  holds just one item.
- Matching ("shapeless"): a recipe matches when the grid holds EXACTLY its ingredients:
    1. the number of items in the grid equals the recipe's total (no extra items)
    2. every ingredient appears the right number of times
  The position of the items does not matter.
- Preview vs real. Two flags describe what is "not real yet":
    IsResultPreview  the grid matches a recipe; the result slot shows the result
    IsGridPreview    a crafted item waits on the result slot; the grid shows its materials
- Crafting: after every change UpdateCraftPreview looks for a match. Taking the result
  (MoveResultToInventory) is what really crafts: first Inventory.HasRoomFor checks there
  is room, then the result is added with AddItem and the grid is emptied.
- Uncrafting: MoveToResult puts a crafted item on the result slot (grid must be empty,
  and a recipe must make that item). The grid fills with previews of the ingredients.
  Taking the first material (MoveGridToInventory) finishes it: the material goes into the
  inventory, the crafted item is used up, and the other previews become real items.
  Taking the crafted item back (MoveResultToInventory) cancels instead.
- ReturnEverythingToInventory is for closing the panel later: real items go back,
  previews are cleared, and what does not fit stays in the grid.
- Inventory got one helper: HasRoomFor(item, amount). It only counts free space and never
  changes anything.

MANUAL PLAY-MODE TEST (teacher)
There is no crafting UI yet, so the test is short:
1. Press Play. Select the Player. In the Inspector, CraftingGrid shows 3 recipes and
   9 empty Grid Slots plus a Result Slot.
2. Walk around: there are 9 coins (left of the start) and 3 gems (right).
   Pick them all up: coins stack in one box, each gem takes its own box.
3. Everything from Inventory Basics still works (1-6, Q, E, punch, kick, jump).
4. Optional: Tools > Validate Crafting (Editor, not Play mode) shows [SUMMARY] 0 failed.
