MILESTONE 4 - CRAFTING SYSTEM: PLAN
Project: Module10_TNI (Unity 6.3 LTS, URP, Input System)
Scene: ThirdPerson only (FirstPerson is out of scope)
Date: 2 Nov 2026

==================================================================
GOAL
==================================================================
The player presses C (or clicks "Craft (C)") to open a crafting panel:
a 3x3 grid, a two-way arrow and one result slot. Items are dragged between
the hotbar and the panel.
- Crafting:   materials in the grid -> a half-transparent preview of the
              result -> drag the result to the hotbar to really craft it.
- Uncrafting: a crafted item on the result slot -> half-transparent previews
              of its materials -> drag one material to the hotbar to really
              take the item apart.

Ideas the students learn:
- Recipes as data (a ScriptableObject that lists ingredients and a result)
- A crafting grid as a list of slots (reusing InventorySlot)
- Matching a recipe: the right number of each ingredient and nothing else
- Preview vs real: nothing changes until the player takes the result
- Uncrafting: the same recipe read backwards
- Drag and drop between UI slots (EventSystem + drag-and-drop interfaces)
- Opening a menu: free the cursor and pause player controls

Recipes (shapeless: position in the grid does not matter):
  GoldBar          4 Coin                   -> 1 Gold Bar          (stack 10, not usable)
  BigHealthPotion  2 Health Potion + 1 Gem  -> 1 Big Health Potion (stack 3, heals 60)
  GemRing          1 Gold Bar + 1 Gem       -> 1 Gem Ring          (stack 1, not usable)

==================================================================
DESIGN DECISIONS
==================================================================
- Logic and UI are split. CraftingGrid (on the Player) holds the 9 grid
  slots, the result slot and the recipes and does every move. It has no UI
  code, so the validation tool can test it without Play mode. The UI scripts
  only draw that state and forward drops to CraftingGrid.
- Two "preview" flags keep the state easy to explain:
    result preview = the grid matches a recipe; the result is not real yet
    grid preview   = an item is being uncrafted; the materials are not real yet
- Every grid slot holds one item. "Count the coins in the grid" is the whole
  matching rule.
- Dropping onto the hotbar always uses Inventory.AddItem, so the normal
  stacking rules choose the slot (the box you drop on is not important).
- One small addition to Inventory: HasRoomFor(item, amount). Crafting checks
  it before taking the result so a full inventory changes nothing.
- A drag only changes data when it is dropped on a valid slot. A cancelled
  drag needs no undo: the source just stops looking half transparent.
- Drag source is read from eventData.pointerDrag (the standard Unity way),
  so no shared "currently dragged" variable is needed.
- Script list as suggested in the task. CraftingPanelUI sits on an
  always-active "Crafting" object (a script on the hidden panel itself would
  stop running when the panel is hidden).
- The two-way arrow is a generated sprite (the default TMP font has no
  arrow glyph).

==================================================================
HOW WE BUILD AND TEST (every sprint)
==================================================================
- Assets/Editor/CraftingSceneSetup.cs (menu Tools/Setup Crafting Scene)
  creates the items, icons, recipes, pickups and UI with the Unity API.
  Safe to run twice. Run it after Tools/Setup Inventory Scene.
- Assets/Editor/CraftingValidation.cs (menu Tools/Validate Crafting) runs the
  Inventory Basics checks plus the crafting checks, without Play mode.
- Both run in batchmode. A sprint is done when the compile log has zero
  "error CS" and the validation log has zero [FAIL].
- The teacher runs the manual Play-mode list from each SprintDoc.
